# REST API To-Do List

Простой REST API для управления списком задач, написанный на Go с использованием [gorilla/mux](https://github.com/gorilla/mux). Задачи хранятся в памяти, доступ к ним потокобезопасный (`sync.RWMutex`).

## Возможности

- создание, получение и удаление задач;
- отметка задачи как выполненной и снятие отметки;
- получение списка всех задач или только невыполненных;
- JSON-ответы с понятными HTTP-кодами ошибок.

## Запуск

```bash
go run .
```

Сервер запускается на порту `9091`. Требуется Go 1.25+.

## Эндпоинты

| Метод    | Путь                    | Описание                                  |
|----------|-------------------------|-------------------------------------------|
| `POST`   | `/tasks`                | Создать задачу                            |
| `GET`    | `/tasks`                | Получить все задачи                       |
| `GET`    | `/tasks?completed=true` | Получить невыполненные задачи             |
| `GET`    | `/tasks/{title}`        | Получить задачу по названию               |
| `PATCH`  | `/tasks/{title}`        | Отметить задачу выполненной / невыполненной |
| `DELETE` | `/tasks/{title}`        | Удалить задачу                            |

Название задачи (`title`) уникально и служит её идентификатором.

## Примеры

Создать задачу (`Title` и `Description` обязательны):

```bash
curl -X POST http://localhost:9091/tasks \
  -d '{"Title": "Купить молоко", "Description": "2 литра"}'
```

Отметить задачу выполненной (`false` снимает отметку):

```bash
curl -X PATCH http://localhost:9091/tasks/Купить%20молоко \
  -d '{"Complete": true}'
```

## Коды ответов

- `201` — задача создана;
- `200` — успешный запрос;
- `204` — задача удалена;
- `400` — некорректное тело запроса или пустые поля;
- `404` — задача не найдена;
- `409` — задача с таким названием уже существует;
- `500` — внутренняя ошибка сервера.

## Ограничения

Данные хранятся только в памяти и пропадают при перезапуске сервера.
